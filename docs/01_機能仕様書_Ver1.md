# WebP Folder Converter Ver.1 機能仕様書

- 文書版: 1.0
- 作成日: 2026-10-11
- 対象OS: Windows 11（64ビット）
- 対象利用者: 個人利用者1名

## 1. 目的

Windows 11のエクスプローラーでフォルダを選び、右クリックメニューから、そのフォルダ直下にあるPNG・JPEG画像をWebPへ一括変換する。日常のWeb制作で迷わず使え、元画像を損なわないことを最優先とする。

## 2. Ver.1の方針

Ver.1は、実装と保守が簡単で故障箇所の少ない「ユーザー単位の静的シェルコマンド」を採用する。

本ツールは特定のWeb制作案件に付属するスクリプトではなく、Windowsへ一度インストールして継続利用する独立ツールとする。WordPress、静的HTML、Astro、Nuxt.jsなど、フォルダの用途や開発技術を判定せず、エクスプローラーで選ばれた任意のフォルダを同じ規則で処理する。

ツール専用のNode.jsランタイムとSharpをアプリ本体に同梱する。利用PCにNode.js、npm、Sharp、Codex、VS Codeがインストールされていなくても実行でき、各案件へ `package.json` や `node_modules` を追加しない。

Windows 11では、この方式で登録した項目は原則として次の場所に表示される。

1. 対象フォルダを右クリックする。
2. 「その他のオプションを確認」を選ぶ（または `Shift + F10`）。
3. 「WebPに変換」を選ぶ。

「WebPに変換」をWindows 11の新しい右クリックメニューの最上位へ直接表示することは、Ver.1の対象外とする。最上位へ表示するには、ネイティブCOMの `IExplorerCommand` と、MSIXまたはsparse packageによるアプリIDが必要になり、個人用の簡易ツールとしては構成・保守・署名・配布確認が過剰になるためである。

## 3. 対象範囲

### 3.1 対象

- フォルダ項目を右クリックした場合
- 選択フォルダ直下の通常ファイル
- 拡張子が `.png`、`.jpg`、`.jpeg` のファイル（大文字・小文字を区別しない）
- ローカルドライブ、接続済みドライブ、通常のUNC共有上のフォルダ。ただし書き込み権限があること

### 3.2 対象外

- サブフォルダ内の画像
- 画像ファイル自体を右クリックした場合
- フォルダ背景の右クリック
- ショートカットやシンボリックリンク経由の画像
- PNG・JPEG以外の形式
- アニメーション画像
- Windows 10、Windows Server、32ビットWindowsの正式サポート

## 4. 機能要件

| ID | 要件 | Ver.1の動作 |
|---|---|---|
| F-01 | 起動 | フォルダの右クリックメニューに「WebPに変換」を表示する |
| F-02 | 一括変換 | 選択フォルダ直下のPNG・JPEGをすべて列挙して変換する |
| F-03 | 保存先 | 元画像と同じフォルダへ保存する |
| F-04 | 元画像保護 | 元画像を変更・移動・削除しない |
| F-05 | 上書き防止 | 出力先の同名 `.webp` が存在する場合はスキップする |
| F-06 | 画質 | WebP画質を80とする |
| F-07 | 透過 | PNGのアルファチャンネルを維持し、アルファ品質は100とする |
| F-08 | 非再帰 | サブフォルダを探索しない |
| F-09 | 名前 | ベース名を変えず、拡張子だけを `.webp` にする |
| F-10 | 継続性 | 1ファイルの失敗で全体を中止せず、残りを処理する |
| F-11 | 向き | JPEGのEXIF Orientationを画素へ反映してから出力する |
| F-12 | 結果表示 | 完了、スキップ、失敗の件数と失敗理由を表示する |
| F-13 | ログ | 実行結果をローカルログへ記録する |
| F-14 | 多重起動 | 異なるフォルダでの複数起動を許容する。同一出力への上書きはしない |
| F-15 | 案件非依存 | WordPress等の構成ファイルを探索せず、任意フォルダを同じ方法で処理する |
| F-16 | 自己完結 | 同梱した専用Node.jsとSharpで動き、PCや案件のNode.js環境に依存しない |

## 5. 詳細な変換ルール

### 5.1 ファイル名

- `photo.png` → `photo.webp`
- `PHOTO.JPEG` → `PHOTO.webp`
- `商品画像 01.jpg` → `商品画像 01.webp`
- 複数のドットを含む `hero.pc.2x.png` → `hero.pc.2x.webp`
- 拡張子は常に小文字の `.webp` とする。

### 5.2 出力競合

出力先が既に存在する場合、ファイルサイズや更新日時にかかわらずスキップする。既存ファイルを開いたり検証したりせず、上書きもしない。

同じフォルダに `sample.png` と `sample.jpg` の両方がある場合、両者の出力先は `sample.webp` となる。この「入力同士の出力名競合」は変換前に検出し、どちらも変換せず、両方を競合スキップとして報告する。先に処理された方だけが残るという不定な動作を避けるためである。

Windowsのファイル名比較に合わせ、出力先名の競合判定は大文字・小文字を区別しない。

### 5.3 画質と画像情報

- `quality: 80`
- `alphaQuality: 100`
- `effort: 4`
- PNGの透過を維持する。
- JPEGのEXIF Orientationは `autoOrient()` で反映する。
- EXIF、GPS、コメントなどのメタデータは出力へ引き継がない。Web制作向けの容量削減とプライバシー保護を優先する。
- リサイズ、切り抜き、色調補正は行わない。
- ICCプロファイルについては、Sharpの標準処理に従いWeb表示向けの色として出力する。厳密な印刷用色管理は対象外とする。

## 6. 実行時の表示

起動時にコンソールを表示し、少なくとも次を日本語で示す。

- 対象フォルダ
- 対象ファイル数
- 各ファイルの状態: 変換、スキップ、失敗
- 最終集計: 対象、成功、既存スキップ、競合スキップ、失敗、所要時間

終了時は小さな結果ダイアログを表示する。成功時は集計のみ、失敗がある場合は集計とログファイルの場所を示す。コンソールは処理終了後に閉じてよい。

例:

```text
WebP変換が完了しました。
成功: 18
既存のためスキップ: 3
名前競合のためスキップ: 0
失敗: 1
ログ: C:\Users\<user>\AppData\Local\WebPFolderConverter\logs\20261011-143012.log
```

## 7. エラー処理

### 7.1 ファイル単位エラー

以下は対象ファイルだけを失敗扱いとし、次のファイルへ進む。

- 壊れた画像、拡張子と実体が一致しない画像
- 読み取り不可
- 出力先への書き込み不可
- ディスク空き容量不足
- Sharpが対応できない画像仕様
- 変換中に入力が削除・変更された

一時出力が残った場合は、そのファイルの処理内で削除を試みる。削除に失敗しても元画像と既存WebPには触れず、ログへ記録する。

### 7.2 実行全体の致命的エラー

以下の場合は画像処理を始めずに終了する。

- フォルダ引数がない、存在しない、またはフォルダでない
- Node.jsまたはSharpを読み込めない
- 対象フォルダを列挙できない
- ログ保存先を作成できず、かつ代替の一時ログも作成できない

### 7.3 終了コード

- `0`: 致命的エラーなし。個別失敗なし（スキップは許容）
- `1`: 起動・設定・フォルダ列挙などの致命的エラー
- `2`: 処理は完了したが、1件以上のファイル変換に失敗

## 8. 性能・大量画像対応

- 全画像を一度にメモリへ読み込まない。
- 変換ワーカー数の初期値は `min(4, 論理CPU数)` とする。
- 同時処理数は環境変数または設定ファイルで将来変更可能な内部定数にするが、Ver.1ではUI設定を設けない。
- 事前列挙後、固定数のワーカーで順次処理する。
- 1万件程度のファイル名列挙でも、入力ファイルの内容を事前読込しない。
- 変換ごとの一時ファイルは出力先と同じフォルダに置き、完了時に排他的に確定する。
- Ctrl+Cやプロセス終了後に残り得る本ツール固有の一時ファイルは、次回起動時に24時間以上経過したものだけ削除候補とする。元画像や通常の `.webp` は削除しない。

## 9. 日本語・特殊文字対応

- Node.jsの文字列とWindowsのUnicodeパスを使用する。
- フォルダパスはシェル文字列として組み立て直さず、1つの引数として受け渡す。
- 日本語、空白、丸括弧、`&`、`'`、`#`、複数ドットを含む名前を試験対象に含める。
- パスの表示とログはUTF-8とする。
- Windows予約名や末尾の空白・ピリオドなど、Windows自身が通常作成できない名前は対象外とする。

## 10. セキュリティ・安全性

- レジストリは `HKEY_CURRENT_USER` 配下だけを変更し、管理者権限を要求しない。
- 実行時のネットワーク通信を行わない。
- 入力パスをコマンドとして再評価しない。
- 外部コマンドへファイル名を文字列連結で渡さない。
- サブフォルダを探索せず、シンボリックリンクを追跡しない。
- 元画像の削除、移動、書換えを行わない。
- 出力確定時にも排他的作成を用い、チェック後の競合発生でも上書きしない。
- ビルド時のnpm依存はバージョンと整合性情報を `package-lock.json` に固定する。
- リリース物には検証済みのNode.jsランタイムとWindows x64用Sharpを同梱し、インストール時・実行時ともインターネット接続を不要とする。
- Node.js、Sharp、libvips等のライセンス文書と第三者通知をリリース物に含める。

## 11. 受入基準

次をすべて満たせばVer.1を受入可能とする。

1. Windows 11でフォルダを右クリックし、「その他のオプションを確認」内に「WebPに変換」が表示される。
2. PNG、JPG、JPEGを同一操作で変換できる。
3. 直下だけが処理され、サブフォルダ内は変化しない。
4. 元画像のハッシュと更新日時が変化しない。
5. 既存WebPがバイト単位で変化しない。
6. 出力名が元のベース名＋ `.webp` になる。
7. 透明PNGの出力にアルファチャンネルがある。
8. 日本語・空白・記号を含むフォルダとファイルを処理できる。
9. 壊れた画像が1件あっても、他の正常画像が変換される。
10. 0件のフォルダでも正常終了し、0件と表示する。
11. PNGとJPEGでベース名が衝突すると、両方を変換せず報告する。
12. アンインストール後、右クリック項目が消え、元画像と生成済みWebPは残る。
13. PCのPATHに `node` と `npm` がない状態でも、右クリック変換が動作する。
14. WordPress、静的HTML、Astro、Nuxt.jsの各フォルダで、プロジェクトへのファイル追加なしに同じ操作で動作する。
15. CodexとVS Codeを終了した状態でも動作する。

## 12. Ver.1で行わないこと

- Windows 11新メニュー最上位への直接統合
- 画質選択画面、GUI設定画面
- サブフォルダ再帰
- 元画像削除
- WebPの再変換
- AVIF、GIF、TIFFなどの対応
- 自動更新、テレメトリ、クラウド同期
- 複数フォルダ同時選択の保証
