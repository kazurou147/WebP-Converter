# WebP Folder Converter 技術設計書

- 対象バージョン: Ver.1
- 作成日: 2026-10-11

## 1. 技術構成の結論

| 項目 | 採用技術 | 理由 |
|---|---|---|
| 変換本体 | ツール同梱のNode.js（LTS、Windows x64） | Unicodeパス、非同期I/O、個人開発での保守性、PC側Node.jsからの独立 |
| 画像変換 | ツール同梱のSharp | PNG/JPEG入力とWebP出力、Windows x64用ビルドが利用しやすい |
| 起動ラッパー | Windows PowerShell 5.1 | Windows 11標準搭載、引数をUnicode文字列として扱える |
| 右クリック登録 | HKCUの静的Shell verb | 管理者権限不要、構成が単純、登録・削除が確実 |
| インストーラー | PowerShellスクリプト | ファイル配置、依存確認、レジストリ登録を一括化 |
| ログ | UTF-8テキスト | 追加ソフトなしで読め、障害調査が容易 |

Node.jsの具体的なメジャーバージョンは実装時点のActive LTSまたはMaintenance LTSから固定し、リリースマニフェストへ正確なバージョンとSHA-256を記録する。最新Current版を無条件に採用しない。利用PCのPATHにあるNode.jsは参照せず、常にアプリ内の `runtime\node.exe` を絶対パスで起動する。

## 1.1 プロジェクト非依存性

- Web制作案件内へツール本体、依存パッケージ、設定、ログを置かない。
- `package.json`、`node_modules`、WordPress、Astro、Nuxt等の有無を判定しない。
- 選択フォルダを単なる画像格納フォルダとして扱う。
- 案件のNode.jsバージョン、パッケージマネージャー、ビルド処理、Git状態を変更しない。
- Codex、VS Code、ターミナル、Webサーバーが起動していなくても利用できる。
- 変換結果だけを選択フォルダへ保存し、それ以外のツールデータは固定インストール先へ保存する。

## 2. Windows 11右クリックメニュー設計

### 2.1 採用方式

ユーザー単位で以下を登録する。

```text
HKEY_CURRENT_USER\Software\Classes\Directory\shell\WebPFolderConverter
  (Default) = WebPに変換
  MUIVerb   = WebPに変換
  Icon      = <インストール先のアイコンまたは実行ファイル>

HKEY_CURRENT_USER\Software\Classes\Directory\shell\WebPFolderConverter\command
  (Default) = powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<install>\invoke.ps1" "%1"
```

`%1` は選択されたフォルダのフルパスである。実際の登録は `.reg` の固定文面ではなく、インストール先を正しくエスケープできる `install.ps1` から.NETのRegistry APIを用いて行う。

### 2.2 表示場所

静的Shell verbはWindows 11の従来メニューに表示される。

```text
フォルダを右クリック
  └─ その他のオプションを確認
       └─ WebPに変換
```

これはVer.1の正式な操作経路である。Windows 11の新しいメニューへ直接表示する方式は、Microsoftが案内する `IExplorerCommand` 実装、ネイティブCOM DLL、アプリID、MSIX/sparse packageが必要であるため採用しない。

### 2.3 登録対象をDirectoryだけにする理由

- `Directory\shell`: 選択したフォルダ項目に対するコマンド
- `Directory\Background\shell`: 開いているフォルダの余白に対するコマンド

Ver.1の要件は「フォルダを右クリック」であるため、誤操作経路を増やさず `Directory\shell` だけを登録する。将来、背景右クリックが必要になった場合は別のキーと `%V` の動作試験を追加する。

## 3. 配置構成

開発時:

```text
webp-folder-converter/
├─ package.json
├─ package-lock.json
├─ src/
│  └─ convert-webp.mjs
├─ scripts/
│  ├─ install.ps1
│  ├─ uninstall.ps1
│  └─ invoke.ps1
├─ assets/
│  └─ webp-converter.ico
├─ test/
│  ├─ unit/
│  └─ fixtures/
└─ README.md
```

インストール時:

```text
%LOCALAPPDATA%\Programs\WebPFolderConverter\
├─ package.json
├─ package-lock.json
├─ node_modules\
├─ runtime\
│  ├─ node.exe
│  └─ LICENSE
├─ src\convert-webp.mjs
├─ invoke.ps1
├─ uninstall.ps1
├─ assets\webp-converter.ico
└─ THIRD-PARTY-NOTICES.txt

%LOCALAPPDATA%\WebPFolderConverter\
└─ logs\
```

実行ファイルはユーザー固有の `%LOCALAPPDATA%\Programs`、可変ログは `%LOCALAPPDATA%\WebPFolderConverter` に分離するため、管理者権限を不要にする。どちらもWeb制作案件の外にあり、案件を移動・削除してもツールは残る。インストール先は空白や日本語を含み得るものとして、常に引用して扱う。

## 4. コンポーネント設計

### 4.1 install.ps1

責務:

1. 64ビットWindows 11であることを確認する。
2. 配布物マニフェストのSHA-256と、同梱ファイルの整合性を確認する。
3. 配布元ディレクトリから固定インストール先へ、同梱Node.js、Sharp、アプリ本体、ライセンスをコピーする。
4. 同梱 `runtime\node.exe` のバージョンを確認する。
5. 同梱Node.jsからSharpを読み込み、簡単な自己診断を行う。
6. HKCUへ右クリックメニューを登録する。
7. 登録内容を読み戻し、実ファイルの存在とコマンド文字列を検証する。
8. インストール結果と利用方法を表示する。

途中で失敗した場合は、作成済みのレジストリキーを残さない。既存バージョンがある場合は、バックアップなしに不完全な状態へ置換しないよう、ステージングディレクトリで準備してから入れ替える。

### 4.2 invoke.ps1

責務:

1. `[string]$FolderPath` を位置引数として受け取る。
2. `$PSScriptRoot\runtime\node.exe` を絶対パスで起動する。PATH上の `node.exe` は使わない。
3. フォルダパスを単一の引数としてNodeへ渡す。
4. 標準出力・標準エラーをコンソールへ表示する。
5. Nodeが出力した結果JSONまたは結果ファイルを読み、Windowsの結果ダイアログを表示する。
6. Nodeの終了コードを自身の終了コードとして返す。

パスを含むコマンド文字列を `Invoke-Expression` へ渡してはならない。PowerShellの呼び出し演算子 `&` と引数配列を使用する。

### 4.3 convert-webp.mjs

責務:

- 引数検証
- 直下ファイル列挙
- 対象拡張子の抽出
- 出力名競合の事前検出
- 既存出力のスキップ
- 固定ワーカープールでの変換
- 一時ファイルからの安全な確定
- 進捗、集計、ログ、終了コード

推奨する処理の流れ:

```text
起動
  ↓
フォルダ検証
  ↓
readdir(withFileTypes: true)
  ↓
通常ファイルかつ png/jpg/jpeg のみ抽出
  ↓
出力先名を計算し、大文字小文字を無視して競合を検出
  ↓
既存WebP・入力競合をスキップ分類
  ↓
最大4ワーカーで変換
  ↓
ファイル単位の成否を収集
  ↓
ログ保存・集計表示・終了
```

## 5. 変換処理設計

### 5.1 Sharpパイプライン

概念コード:

```js
await sharp(inputPath, { failOn: 'error' })
  .autoOrient()
  .webp({
    quality: 80,
    alphaQuality: 100,
    effort: 4,
    exact: true
  })
  .toFile(tempPath);
```

`exact: true` は完全透明ピクセルに含まれるRGB値も保持する指定で、合成処理時の意図しない縁色変化を避ける側に倒す。出力後にメタデータまたはSharpの結果情報を確認し、形式がWebPであること、幅と高さが正であることを検証する。

### 5.2 安全な出力確定

処理順:

1. 変換開始直前に出力先の存在を再確認する。
2. 同じ出力フォルダへ本ツール固有の一時名で書く。
3. 一時ファイルのWebP形式と寸法を確認する。
4. 排他的な方法で最終名を作成する。
5. 最終名がその間に作成されていた場合は、既存を保持してスキップ扱いにする。
6. 一時ファイルを削除する。

一時名の例:

```text
.webp-folder-converter.<pid>.<random>.tmp
```

単純な `rename(temp, output)` だけに依存してはならない。プラットフォームやファイルシステムによって既存宛先の扱いが異なるため、排他的確定を保証する。NTFSでは一時ファイルのハードリンクを最終名として排他的に作成し、成功後に一時名を削除する方法を第一候補とする。ハードリンク非対応の共有・ファイルシステムでは、`COPYFILE_EXCL` を使うフォールバックを実装し、既存を上書きしない。

### 5.3 ワーカープール

- 外部の並列制御パッケージは追加せず、小さなワーカープールを標準APIで実装する。
- 初期ワーカー数は `Math.max(1, Math.min(4, os.availableParallelism()))`。
- キュー内のパスだけを保持し、入力画像本体は各ワーカーで必要時に読む。
- `Promise.all` で全ファイルを一斉起動しない。
- Sharp内部も並列処理を行うため、ワーカー数をCPU数いっぱいまで増やさない。

## 6. エラー・ログ設計

### 6.1 ログ形式

UTF-8の1実行1ファイル。ファイル名はローカル日時を用いる。

```text
%LOCALAPPDATA%\WebPFolderConverter\logs\20261011-143012-123.log
```

最低限の内容:

- ツール、Node.js、Sharpのバージョン
- 開始・終了日時
- 対象フォルダ
- 設定値（画質、ワーカー数、再帰なし）
- 各ファイルの結果と正規化したエラー概要
- 最終集計と終了コード

スタックトレースはログにだけ記録し、結果ダイアログには表示しない。ログは直近30ファイルを保持し、それを超える古い本ツールログだけを削除する。ログ削除失敗は変換失敗にしない。

### 6.2 結果分類

```js
{
  converted: [],
  skippedExisting: [],
  skippedConflict: [],
  failed: []
}
```

失敗オブジェクトには入力パス、出力パス、安定したエラー種別、利用者向けメッセージ、内部エラーを保持する。ファイル内容をログへ出力しない。

## 7. 日本語パス設計

- PowerShellからNodeへは引数配列で渡す。
- Nodeでは `process.argv` を使用し、再度コマンドライン文字列として解釈しない。
- パス処理は `node:path` の `parse`、`join`、`resolve` を使う。
- ファイル列挙は `fs.promises.readdir` を使い、文字コード指定を変更しない。
- ログ書込みは明示的に `utf8`。
- 大文字小文字を無視する競合キーは、少なくとも `outputName.normalize('NFC').toLocaleLowerCase('en-US')` 相当で作る。ただし実在判定の最終根拠はファイルシステム操作とする。
- パス長についてはNode/Sharpで扱える範囲を利用し、独自に260文字で切り捨てない。長いパスは受入試験に含めるが、共有側の制限は環境依存としてエラー報告する。

## 8. インストール・更新・アンインストール設計

### 8.1 インストール

- 管理者権限なしで実行する。
- アプリ本体は `%LOCALAPPDATA%\Programs\WebPFolderConverter` に固定する。
- ログは `%LOCALAPPDATA%\WebPFolderConverter\logs` に固定する。
- レジストリ登録はHKCUに限定する。
- インストール時にnpmやネットワーク接続を要求しない。
- Explorer再起動は原則不要。表示されない場合だけ、新しいExplorerウィンドウ、サインアウト、Explorer再起動の順に案内する。

### 8.2 更新

- 同じ `install.ps1` の再実行を更新手順とする。
- 新版は一時ステージへ準備し、Sharp自己診断後に切り替える。
- レジストリは現在の固定パスを再登録する。
- ユーザーログは保持する。

### 8.3 アンインストール

1. 所有するレジストリキーだけを削除する。
2. `%LOCALAPPDATA%\Programs\WebPFolderConverter` を削除する。
3. 既定では `%LOCALAPPDATA%\WebPFolderConverter` のログも削除する。`-KeepLogs` 指定時だけ保持し、実行前に対象を表示する。
4. 生成済みWebPと元画像は削除しない。
5. ツール同梱Node.jsだけをアプリ本体とともに削除し、PCに別途インストールされたNode.jsには触れない。

アンインストーラー自身を含むディレクトリ削除は、別プロセスへ限定的な削除処理を引き継ぐか、元の配布フォルダにある `scripts\uninstall.ps1` から実行する。削除対象の絶対パスが固定インストール先と完全一致することを検証してから再帰削除する。

## 9. セキュリティ設計

- シェル拡張DLLをExplorerプロセス内へロードしない。
- レジストリコマンドはインストール済みの固定スクリプトだけを指す。
- `Invoke-Expression`、`eval`、動的コード生成を使わない。
- 入力拡張子は許可リスト方式。
- シンボリックリンク・ディレクトリ接合点を追わない。
- 出力既存チェックに加え、確定操作も排他的にする。
- npmによるSharpの取得は開発・リリース作成時だけ行い、利用PCのインストール時には行わない。
- `package-lock.json` を必須とし、リリース作成時に `npm audit` とSharp自己診断を確認する。
- Node.js公式Windows x64バイナリとSharpのWindows x64用ビルドをリリースへ固定し、バージョン、SHA-256、ライセンスを記録する。
- インストール時および実行時に外部URLへアクセスしない。
- PowerShellの `ExecutionPolicy Bypass` は登録済みの `invoke.ps1` 1回のプロセスにだけ適用し、システム設定は変更しない。

## 10. テスト設計

### 10.1 自動テスト

- 拡張子判定（大小文字を含む）
- 出力名生成
- 競合検出
- 既存出力スキップ
- 壊れた画像後の継続
- 透明PNGのアルファ有無
- EXIF Orientation適用後の寸法
- 非再帰
- 一時ファイル後始末
- 終了コード0/1/2
- 日本語、空白、`&`、括弧を含むパス

### 10.2 Windows実機テスト

- Windows 11の「その他のオプションを確認」に表示されること
- HKCUのみで登録され、UACが出ないこと
- PATHからNode.jsを除いた状態でも、同梱ランタイムで動作すること
- 案件フォルダに `node_modules`、設定、ログが作られないこと
- ローカルNTFS、OneDrive同期フォルダ、UNC共有（利用環境にある場合）
- 読取専用フォルダ、空き容量不足相当、開かれているファイル
- 二重起動による同一出力競合
- アンインストール後のメニュー消失

## 11. 将来拡張

優先順位案:

1. 設定ファイルによる画質・並列数の変更
2. フォルダ背景メニュー
3. サブフォルダ再帰の明示オプション
4. AVIF出力
5. 処理前の見積り・処理後の削減容量表示
6. Windows 11新メニューの最上位統合

最上位統合を行う場合は、変換本体はNode/Sharpのまま再利用し、薄いx64ネイティブランチャーだけを `IExplorerCommand` として実装する。COM側では変換を実行せず、`Invoke` 後に別プロセスを起動してExplorerのUIスレッドを塞がない。MSIX/sparse packageの署名、登録、更新、アンインストールを別プロジェクトとして扱う。
