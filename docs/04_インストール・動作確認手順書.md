# WebP Folder Converter インストール・動作確認手順書

- 対象: Ver.1
- OS: Windows 11 64ビット

## 1. 前提

- Windows 11へ通常ユーザーとしてサインインしていること
- インストールおよび利用に管理者権限は不要
- Node.js、npm、Sharp、Codex、VS Codeのインストールは不要
- インストール時・実行時ともインターネット接続は不要

本ツールは専用のNode.jsランタイムとSharpを同梱する。PCに別のNode.jsが入っていても使用せず、そのバージョンを変更しない。

## 2. インストール

1. 配布フォルダをローカルPCへ展開する。
2. 配布フォルダでPowerShellを開く。
3. 次を実行する。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1
```

4. インストーラーが次をすべて成功と表示することを確認する。

   - Node.js確認
   - ファイル配置
   - 配布ファイルの整合性確認
   - 同梱Node.jsの確認
   - Sharp自己診断
   - 右クリックメニュー登録
   - 登録内容の読戻し確認

5. エクスプローラーを新しく開く。

インストール先は次である。

```text
%LOCALAPPDATA%\Programs\WebPFolderConverter
```

ログだけは次へ保存される。

```text
%LOCALAPPDATA%\WebPFolderConverter\logs
```

WordPress、静的HTML、Astro、Nuxt.jsなどの案件フォルダには、Node.js、Sharp、設定、ログを追加しない。

レジストリは現在の利用者の次の場所だけに登録される。

```text
HKEY_CURRENT_USER\Software\Classes\Directory\shell\WebPFolderConverter
```

## 3. 基本動作確認

### 3.1 テスト用フォルダの準備

既存の大切な画像ではなく、コピーしたテスト画像を使用する。例えば次を用意する。

```text
WebP変換テスト（日本語）\
├─ 写真 01.jpg
├─ 透明ロゴ.png
├─ SAMPLE.JPEG
├─ 既存.png
├─ 既存.webp
├─ 壊れた画像.jpg
└─ subfolder\
   └─ サブ画像.png
```

`壊れた画像.jpg` は、テキストファイルの拡張子だけを `.jpg` にしたテストファイルとする。`既存.webp` は、`既存.png` と同じベース名で準備する。

### 3.2 右クリックから実行

1. 「WebP変換テスト（日本語）」フォルダ自体を右クリックする。
2. Windows 11の「その他のオプションを確認」を選ぶ。キーボードでは `Shift + F10` でもよい。
3. 「WebPに変換」を選ぶ。
4. コンソールに処理状況が表示されることを確認する。
5. 完了後、結果ダイアログが表示されることを確認する。

### 3.3 期待結果

- `写真 01.webp` が作成される。
- `透明ロゴ.webp` が作成され、透過が保たれる。
- `SAMPLE.webp` が作成される。
- 既存の `既存.webp` はスキップされ、内容・更新日時が変わらない。
- `既存.png` は残る。
- `壊れた画像.jpg` は失敗として報告される。
- 壊れた画像があっても、他の正常画像は変換される。
- `subfolder\サブ画像.webp` は作成されない。
- すべての元PNG・JPEGが残り、更新日時が変わらない。

## 4. 必須確認項目

### 4.1 上書き防止

同じフォルダでもう一度「WebPに変換」を実行する。1回目に生成されたWebPがすべて既存スキップになり、内容と更新日時が変わらないことを確認する。

重要な確認では、PowerShellの `Get-FileHash` を実行前後に使う。

```powershell
Get-FileHash -Algorithm SHA256 '.\WebP変換テスト（日本語）\既存.webp'
```

### 4.2 元画像保護

元画像についても実行前後のSHA-256が同じことを確認する。

```powershell
Get-FileHash -Algorithm SHA256 '.\WebP変換テスト（日本語）\写真 01.jpg'
```

### 4.3 非再帰

サブフォルダの画像と更新日時が変わらず、WebPが作成されないことを確認する。

### 4.4 入力名競合

空のテストフォルダに次を用意する。

```text
same.png
same.jpg
```

実行後、`same.webp` が作成されず、2件が名前競合として報告されることを確認する。

### 4.5 日本語・記号

次のような名前でも成功することを確認する。

```text
制作素材 & 確認用（秋）\商品画像 #1.png
```

### 4.6 案件非依存と自己完結

次の条件で同じ右クリック操作が成功することを確認する。

- WordPress案件の画像フォルダ
- 静的HTML案件の画像フォルダ
- Astro案件の `public` または `src/assets` 相当のテストフォルダ
- Nuxt.js案件の `public` または `assets` 相当のテストフォルダ
- Web制作案件ではない通常の画像フォルダ

各フォルダに新しく作られるものが対象の `.webp` だけであることを確認する。`package.json`、`node_modules`、設定、ログは作られてはならない。

Codex、VS Code、開発サーバーをすべて終了してからも動作することを確認する。可能であれば、システムのPATHにNode.jsがない検証用ユーザーまたは環境でも動作を確認する。

## 5. メニューが表示されない場合

次の順に確認する。

1. フォルダの中の余白ではなく、フォルダ項目自体を右クリックしているか。
2. 「その他のオプションを確認」を開いているか。
3. 新しいエクスプローラーウィンドウで試す。
4. 次のコマンドで登録を確認する。

```powershell
Get-Item 'Registry::HKEY_CURRENT_USER\Software\Classes\Directory\shell\WebPFolderConverter'
Get-ItemProperty 'Registry::HKEY_CURRENT_USER\Software\Classes\Directory\shell\WebPFolderConverter\command'
```

5. インストール先に `invoke.ps1` があるか確認する。
6. `install.ps1` を再実行する。
7. それでも表示されなければ、一度サインアウトしてサインインする。Explorerの強制終了は最後の手段とする。

「WebPに変換」が新しい右クリックメニューの1段目に出ないことは、Ver.1では正常仕様である。

## 6. 変換に失敗する場合

結果ダイアログに表示されたログを開く。標準の保存先は次である。

```text
%LOCALAPPDATA%\WebPFolderConverter\logs
```

確認する項目:

- 対象フォルダに書き込み権限があるか
- ディスク空き容量があるか
- 元ファイルを別アプリが排他的に使用していないか
- 拡張子だけでなく実体もPNG/JPEGか
- インストール先の `runtime\node.exe` が削除されていないか
- インストール先の `node_modules\sharp` が破損していないか

Node.jsまたはSharpの読込みエラーの場合は、配布物から `install.ps1` を再実行する。システムへNode.jsやSharpを追加インストールする必要はない。既存WebPを手動削除して再変換する場合は、削除対象を自分で確認してから行う。本ツールは既存WebPを削除しない。

## 7. 更新

1. 新しい配布フォルダを用意する。
2. そのフォルダから `install.ps1` を再実行する。
3. Sharp自己診断とレジストリ読戻しが成功したことを確認する。
4. テスト用フォルダで基本動作確認を行う。

更新によって元画像や生成済みWebPが削除されることはない。

## 8. アンインストール

元の配布フォルダでPowerShellを開き、次を実行する。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\uninstall.ps1
```

確認事項:

- 「その他のオプションを確認」から「WebPに変換」が消える。
- `%LOCALAPPDATA%\Programs\WebPFolderConverter` が削除される。
- `%LOCALAPPDATA%\WebPFolderConverter` のツールログが削除される。
- 元画像と、これまでに生成したWebPは残る。
- ツールに同梱したNode.jsは削除される。PCに別途インストールされたNode.jsは削除されない。

メニューがすぐ消えない場合は、新しいエクスプローラーウィンドウで確認し、必要ならサインアウト・サインインする。

## 9. 安全上の注意

- 本ツールは元画像を削除しないが、初回確認は必ずテスト用コピーで行う。
- 既存WebPは自動更新されない。画質設定を変えて作り直す場合は、対象を確認して自分で既存WebPを退避または削除する。
- インストールフォルダ内のスクリプトを第三者のものへ置き換えない。
- 出所不明の `package-lock.json` や依存パッケージへ差し替えない。
- ログにはローカルのファイルパスが含まれるため、他人へ渡す前に確認する。
